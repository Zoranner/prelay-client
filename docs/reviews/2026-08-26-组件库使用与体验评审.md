# Prelay Client 组件库使用与体验复核

## 结论

Prelay Client 已以统一、低维护的方式接入 `@stellar/ui@0.1.4`。组件库提供基础组件、样式、固定内部图标和全局交互能力；Prelay 提供业务页面、业务状态和业务图标字面量；`@nuxt/icon` 负责扫描、裁剪、生成和运行时注册离线图标。三者没有重复图标实现，也没有业务项目维护组件库内部图标清单。

智能体入口保留“滑杆图标 + 配置”。页面不再使用外层 Card 包裹整个工作区，标题、操作和内容区保持清晰的无框层级。用户已确认现有视觉效果良好；本次没有启动 Nuxt/Tauri 做新的窗口截图验收，因此该结论不替代不同屏幕尺寸下的运行态视觉验证。

## 职责边界

- `@stellar/ui/nuxt` 自动注册组件库样式，并在 `modules:done` 将自己的样式置于业务 CSS 前；宿主不再了解 `@stellar/ui/styles` 或维护样式排序补丁。
- 组件库仅通过 `icon:clientBundleIcons` 提供自身实际固定使用的少量反馈图标，例如 `ph:info`、`ph:check-circle` 和 `ph:x-circle`。它不内置完整图标集，不修改宿主的 Nuxt Icon 配置。
- Prelay 的 `nuxt.config.ts` 使用 `provider: "none"`、`componentName: "NuxtIcon"` 和 `clientBundle.scan: true`。普通的静态字面量，如 `icon="ph:sliders-horizontal"`，由扫描器自动加入离线 bundle，不需要手工登记。
- 运行时动态拼接的图标名无法被静态扫描可靠发现；只有这种场景才由宿主维护有限显式清单。当前 Prelay 未发现动态拼接图标。

开发时普通静态图标的新增由启动扫描生效。`@nuxt/icon` 当前不会对新增图标可靠地热更新客户端 bundle，因此首次新增后重启 Nuxt 开发服务是框架边界；组件库或依赖升级后首次重启同样合理。这不要求改动 `nuxt.config.ts`，更不要求为组件库图标建立业务清单。

## 页面职责

`agents.vue` 保留加载、草稿、连接构造、保存、通知和退出守卫。规则输入与预览滚动同步位于 `AgentRulesEditor.vue`；Codex 与 Claude Code 的字段、选项和局部交互分别位于各自的受控表单组件。此拆分减少了页面级状态和展示细节的耦合，同时不改变保存与放弃修改的行为。

## 验证事实

- Stellar UI 模块测试覆盖固定内部图标、宿主扫描边界、样式顺序与 Nuxt 文档契约。
- Prelay 回归测试覆盖无手工图标清单、无宿主样式补丁、无外层 Card、智能体展示职责与退出守卫。
- `nuxt generate` 成功，生成离线 bundle 为 74 个图标、30.36 KB（未压缩）；其中包含 `ph:sliders-horizontal`、`ph:info`、`ph:check-circle` 与 `ph:x-circle`。
