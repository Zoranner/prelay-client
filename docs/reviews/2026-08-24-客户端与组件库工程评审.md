# Prelay 客户端与组件库工程评审报告

## 评审范围

本次评审覆盖 `prelay-client` 本轮的 Nuxt/Tauri 改动，以及通过 Junction 引用的 `stellar-ui` 本轮改动，重点检查工程边界、质量门禁和本次变更引入的风险。`prelay-server` 与 `prelay-protocol` 工作树均为干净状态，不在本次整改范围内。

## 评审依据

- 工作区 `AGENTS.md` 中的仓库边界、Bun 与 Rust 验证要求。
- `prelay-client`、`stellar-ui` 的 `.editorconfig`、`.gitattributes`、`package.json` 与 Cargo 配置。
- `review-engineering` 的通用、Nuxt/Vue 和 Rust 工程基线。

## 总体结论

客户端本次改动保持了服务端、协议仓与桌面端的职责边界。客户端通过 Tauri 原生命令管理本机智能体配置，未增加直接访问管理 API 的路径。已修复 Claude Code 设置保存后静默丢失、草稿退出确认时序和 Markdown 原始 HTML 渲染等问题；客户端与原生端的完整检查均已通过。

组件库的运行测试通过，但类型检查仍不可用，且缺少不改写源码的 lint、格式检查入口。该问题会削弱组件库作为共享依赖时的提交前质量门禁，应单独整改。

## 检查情况

- `prelay-client`：`bun run typecheck` 通过；`bun test` 通过，86 个测试无失败。
- `prelay-client/src-tauri`：执行 `cargo fmt --all`；`cargo clippy --all-targets --all-features -- -D warnings` 通过；`cargo test --all-targets --all-features` 通过，11 个库测试和 46 个集成测试无失败。
- `stellar-ui`：`bun test` 通过，11 个测试无失败。
- `stellar-ui`：`bunx vue-tsc --noEmit` 失败，见下述主要问题。

## 主要问题

### 组件库类型检查不可用

定性：违反硬性工程基线。

`bunx vue-tsc --noEmit` 在 `Tree.vue`、`FileUpload.vue` 报告未使用声明，并在 `tailwind.preset.ts` 报告从 `theme` 导入不存在的 `theme`、`layout`、`colors`。当前 `package.json` 仅提供带 `--fix` 的 `lint` 和写入式 `format` 脚本，未提供只检查的 lint、格式或类型检查入口。共享组件的类型问题无法在提交前稳定阻断，后续修改容易叠加在已失效的门禁之上。

建议单独修复上述类型错误，并提供 `lint:check`、`format:check`、`typecheck` 三个不改写工作树的脚本；不要将自动修复命令作为评审或提交前检查。

### 本次已整改的问题

Claude Code 设置页此前展示接入点与 Opus、Sonnet、Haiku、子智能体模型，但原生端没有将它们写入 `settings.json`，保存后会静默丢失。现已改为读写 Claude Code 官方环境变量，接入点令牌也可从本地配置读回；自定义 Codex API Key 保持回显并可查看。

多个草稿面并存时，退出守卫此前只处理最后注册的面，确认框退场前又会提前解析结果，导致连续丢弃确认被错误拒绝。现已按顶层到低层逐项确认，并在确认框完全退场后再解析。MarkdownViewer 也已关闭原始 HTML，避免规则预览执行本地文件中的 HTML。

## 整改优先级建议

### 建立组件库只读质量门禁

- 修复 `vue-tsc` 当前报告的 5 项错误。
- 增加不改写源码的 lint、格式和类型检查脚本。

### 保持本次客户端边界

- 智能体配置继续只通过 Tauri 原生命令读写本机文件。
- Provider API Key 与 Endpoint Token 的服务端管理边界不因本地智能体配置回显而改变。
