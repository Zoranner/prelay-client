# Prelay Client 工程评审报告

## 评审范围

本次评审覆盖 `prelay-client` 的 Nuxt 4 前端、Tauri/Rust 原生层、集成测试、构建与发布配置。重点核对用户规定的 450 行硬约束、领域目录边界、前端质量门禁和生产构建告警。本次不评价具体业务功能是否符合需求。

## 评审依据

- 用户明确的 450 行脚本硬阈值。
- 项目 `AGENTS.md` 的 Bun、Rust、子模块与工作树约束。
- 当前 `package.json`、`nuxt.config.ts`、`src-tauri/Cargo.toml`、`.github/workflows/release.yml` 和源码实际状态。

## 总体结论

此前识别的 Rust 原生层平铺、前端大文件和缺少前端质量门禁问题已完成结构性整改。Rust 已按 `app`、`agents`、`relay`、`identity`、`extensions`、`preferences`、`commands` 划分职责；前端页面和组件已完成拆分；质量门禁已纳入 lint、格式、类型、测试和构建流程。当前源码扫描未发现超过 450 行的 `.vue`、`.ts`、`.js` 或 `.rs` 文件。

本轮新增的生产构建处理了两个实际告警来源：ECharts 保持动态加载并通过 Rolldown 依赖组拆分，Markdown 展示改用轻量 `codeToHtml` 适配，避免完整 Shiki 语言库和 WASM 进入客户端。Nitro 内联 `@vue/shared` 后，Node `DEP0155` 也不再出现。

## 已完成的结构整改

### Rust 原生层

原先平铺在 `src-tauri/src/` 根目录的业务实现已迁入领域目录。`lib.rs` 只负责 crate 入口，`commands/` 只负责 Tauri command 适配；智能体设置、发现、集成、身份、Relay、扩展和桌面偏好分别由对应领域模块负责。文件名不再依赖前缀表达模块归属。

### 前端组织和质量门禁

智能体页面、设置、扩展目录、统计图表和表格交互已按组件与 composable 拆分。`eslint.config.mjs`、Prettier 检查和 release `verify` 作业已建立统一入口，避免只依赖构建成功来判断前端质量。

### 构建依赖边界

`nuxt.config.ts` 使用 Rolldown `output.codeSplitting` 将共享依赖按 400KB 目标拆分，并保持图表按需加载。`app/utils/shikiLite.ts` 只提供 MarkdownViewer 使用的 `codeToHtml` 契约，负责 HTML 转义和语言标记，不加载完整语法包。

## 后续边界

本轮未修改服务端、协议子模块或远端发布状态。Rust 的完整命令验证未因本轮未修改 Rust 而重复执行；后续 Rust 变更仍必须执行仓库要求的 `cargo fmt --all` 和严格 Clippy。
