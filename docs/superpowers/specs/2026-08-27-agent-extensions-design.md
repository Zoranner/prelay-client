# 智能体扩展库设计

## 目标

在 Prelay 的“智能体”页中发现固定 Gitea 组织 `https://git.kimo.ink/agents` 下的扩展包，预览包说明，并按用户选择安装规则和 Skill 到本机已安装的智能体客户端。

## 范围

首期只读取组织仓库和 `.prelay.json`，不经 Prelay 服务端或共享协议。组织地址固定，不提供来源配置、多源管理、认证令牌或远程脚本执行。

有效 manifest 必须含有 `schema`、`version`、`name`、`summary` 与 `kind`。扩展服务可发现 `rule`、`skill`、`plugin`、`mcp` 四类；桌面端扩展库只展示前三类，MCP 不在目录中展示或安装。没有 manifest、JSON 无效、schema 不为 `1`、字段不完整或 kind 未知的仓库不出现在目录中。

规则、Skill 和插件由原生层安装。规则完整替换各智能体的 `AGENTS.md`；Skill 先清理同包旧目录再完整写入；插件写入 Codex/ChatGPT 的本地文件、缓存和配置。MCP 保留在智能体本地配置的扫描、设置和卸载链路中，不由扩展库安装。

## 交互

“扩展库”位于智能体页左侧客户端列表底部，与 Codex CLI、ChatGPT、OpenCode 之间有分隔线。选中它后，右侧保留当前工作区模式：顶部使用 `规则 / 插件 / Skill` 分段切换，下方是所选类别的表格。

表格只显示名称、版本、摘要和操作，不显示安装状态。操作列固定为查看详情和安装两个图标按钮。查看详情打开右侧抽屉，仅渲染 README 以及包的版本和类型。安装打开普通模态框，不从详情抽屉继续打开嵌套表面。

安装模态框仅允许勾选本机已检测到的客户端。Codex CLI 和 ChatGPT 分别显示但勾选状态联动，底层对共享落点只执行一次写入；Claude Code 独立。模态框在确认前展示实际复制文件、规则合并目标和风险。安装成功后关闭模态框、提示结果并刷新既有客户端清单；失败时保留模态框和有效错误原因。

目录加载失败显示错误状态与刷新操作。分类没有包时显示空表格。扩展库不推断、不显示聚合的安装、更新或冲突状态；客户端原有规则和本机条目清单仍是本机事实的展示来源。

## 本机写入

规则包读取仓库根 `AGENTS.md`，以带包标识的 Prelay 托管 Markdown 段落合并到 `~/.codex/AGENTS.md` 和 `~/.claude/CLAUDE.md`。合并只替换同一包的托管段落，保留所有非托管内容。

Skill 包读取 `skills/` 下的完整目录。Codex CLI 和 ChatGPT 共享复制到 `~/.agents/skills/`；Claude Code 复制到 `~/.claude/skills/`。每个包的解析 commit SHA、仓库 URL、版本、文件清单与安装目标保存在 Prelay 应用数据目录中，以支持后续安全更新和卸载，但首期不在扩展库中展示该状态。

远程内容解析和下载固定到实际查询到的 commit SHA，不能跟随分支名。文件下载、目录复制和配置写入使用临时文件和原子替换；网络、manifest 或本机写入失败不得留下部分安装。

## 验证

Rust 单元测试覆盖 manifest 过滤、固定 commit 解析、规则托管段落合并和 Skill 目标映射。前端测试覆盖扩展库入口、四类分段表格、详情抽屉和安装模态框的结构与交互契约。完成代码后执行仓库规定的 Bun 测试、类型检查、Cargo 格式化、clippy 与测试；运行中的桌面客户端锁阻断 all-targets 测试时如实报告。
