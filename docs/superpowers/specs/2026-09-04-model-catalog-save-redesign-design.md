# 模型目录与智能体配置统一重构设计

## 目标

将供应商、接入点和智能体配置统一到服务端模型目录，消除客户端模板回退和可缺失的目录副本，确保 Codex 的 `models.json` 由服务端目录数据生成。

## 约束与不变量

- `prelay-server/config/catalog` 是模型、显示名称、能力、协议和供应商支持关系的唯一事实源。
- 供应商模型和接入点模型只能引用目录中存在的模型 ID；不存在目录模型的新增或保存请求失败。
- 模型 ID 是保存、查询、筛选、分组、路由和 Codex `slug` 的唯一值；显示名称是目录对象的派生投影。
- 不在数据库保存模型显示名称或能力快照，不增加迁移、索引或兼容数据结构。
- 智能体选择 Prelay 接入点时必须携带对应的完整语言模型目录对象；选择自定义连接时不携带目录对象，也不生成 `models.json`。
- 客户端不再内置供应商或模型模板，不从上游发现模型，不允许自定义供应商模型或接入点对外模型名。
- Provider API Key、Endpoint Token 和设备凭据不进入目录对象、日志或测试夹具之外的持久化数据。

## 当前问题

当前链路在三个位置拆分了同一事实：服务端目录提供完整模型对象，业务响应只提供字符串和显示名，客户端再把目录对象作为每个智能体模型的可选字段传递；Codex 写入函数在字段缺失时读取 `deepseek_models.json`，将与当前接入点无关的模板写入用户配置。目录加载又是异步的，失败后静默使用空索引，因此保存动作无法证明其输入来自服务端目录。

## 目标架构

```text
config/catalog/{models,providers}.toml
        |
        v
prelay-server ProviderCatalog
        |
        +-- 管理 API: /api/catalog（完整目录）
        +-- 供应商/接入点写入校验与响应投影
        |
        v
prelay-client ProviderCatalogResponse（单一索引）
        |
        +-- 供应商和接入点选择器只提交目录 ID
        +-- 智能体 Prelay 连接携带完整语言模型对象
        |
        v
Tauri agent_settings_save
        |
        +-- Prelay: 目录对象原样生成 ~/.codex/models.json
        +-- Custom: 不生成 models.json
```

## 服务端职责

`ProviderCatalog` 继续在启动时加载语言模型、图像模型和供应商关系，并成为所有管理写入的校验入口。

- 创建或更新供应商时，`provider_type` 必须对应目录供应商；模型 ID 必须属于该目录供应商声明的模型集合。
- 创建或更新接入点时，每个映射的对外模型 ID和上游模型 ID必须来自目录及所选供应商的关系；不接受空值、目录外 ID 或自定义对外名称。
- 接入点中同一模型 ID 可以拥有多个供应商路由，但不同模型 ID 不得合并为一个对外模型组。
- Provider、Endpoint、Activity 和 ModelStats 的显示字段继续由 `ProviderCatalog` 投影；不把投影字段写回数据库。
- `/api/catalog` 返回完整 `ProviderCatalogResponse`，包括语言模型和图像模型的全部目录字段。客户端只通过受保护的 Tauri command 读取该接口。

## 协议与客户端状态

完整目录类型继续复用 `CatalogLanguageModelResponse` 和 `CatalogImageGenerationModelResponse`，不新增第二套模型引用类型。

`CodexConnection::Prelay` 不再使用 `catalog_model: Option<CatalogLanguageModelResponse>` 的逐条可缺失结构。它携带接入点选中的完整语言模型目录对象列表；对象的 `id` 同时是 Codex 对外模型 ID。上游路由信息属于服务端接入点，不复制进本地 Codex 配置负载。

客户端应用框架负责加载一次目录并维护明确的加载状态。供应商、接入点和智能体页面只能从同一索引产生选项；目录尚未完成加载时，智能体保存不可执行，不能使用空索引或客户端模板继续保存。自定义智能体连接不依赖目录加载。

## Codex 文件生成

Codex Prelay 保存流程只接受完整语言模型目录对象列表：

1. 校验默认模型 ID 位于该列表。
2. 对每个目录对象序列化全部字段。
3. 将 `slug` 设置为目录对象 `id`，其余字段保持服务端目录值。
4. 原子写入 `~/.codex/models.json`。
5. 将规范化后的文件路径写入 `config.toml` 的 `model_catalog_json`。

删除 `deepseek_models.json` 及其按上游 ID 查找、首项回退和人为覆盖 `display_name` 的逻辑。自定义连接只更新 `config.toml` 和必要的认证文件，不设置 `model_catalog_json`，也不创建新的 `models.json`。

## 错误处理

- 目录接口不可用或目录状态未就绪时，客户端保存返回明确的本地配置错误，不写入半成品 `config.toml`、`models.json` 或认证文件。
- 服务端目录校验失败返回稳定的验证错误；客户端显示该错误，不将其转换成“模型发现失败”或手工添加提示。
- 自定义连接保持独立流程，不因目录加载失败而阻断。

## 验证策略

### 协议

- 序列化测试覆盖完整语言模型对象列表作为智能体保存负载。
- 断言模型对象的能力字段、显示名称和 ID 在 JSON 中保持不变。

### 服务端

- 目录内外模型、供应商关系和接入点映射的创建/更新测试。
- 同一模型 ID 多供应商路由合并、不同模型 ID 不合并的测试。
- 管理响应继续断言显示字段由目录投影，且数据库只保存 ID 和路由数据。

### 客户端

- 目录加载状态、保存前置条件和自定义分支的行为测试。
- 实际构造 Prelay 保存负载，断言每个完整目录对象原样写入 `models.json`，不出现内置模板字段污染。
- 断言默认模型校验、目录对象顺序、`model_catalog_json` 路径和自定义连接不生成目录文件。
- 执行 Bun 定向测试、类型检查、Prettier；Rust 执行 `cargo fmt --all`、Clippy 和 Tauri 设置测试。

## 实施顺序

1. 更新协议中的智能体保存负载，移除可缺失的目录副本。
2. 在服务端加入供应商和接入点目录关系校验，并补齐错误契约测试。
3. 在客户端集中管理目录加载状态，删除模板和上游发现路径，改造智能体保存负载。
4. 重写 Codex 文件生成和设置测试，验证完整目录对象到文件的实际内容链路。
5. 跨仓更新 submodule、复查敏感信息和工作树，按协议、服务端、客户端逻辑拆分提交；不推送、不发布、不修改部署状态。
