# 本地扩展识别设计

## 目标

在 Prelay 客户端中展示员工当前电脑上可供 Codex 和 Claude Code 使用的扩展。首版只识别本地状态，使员工能够确认自己的插件、MCP 和 Skill 是否可用。

## 范围

- 仅支持 Codex 和 Claude Code。
- 仅扫描用户级本地配置和客户端可发现的扩展位置。
- 打开扩展页面时自动扫描，并提供手动刷新。
- 未检测到某个客户端时，不显示该客户端区域。
- 不读取项目目录中的临时配置。
- 不提供安装、卸载、启停、更新、企业清单或服务端下发能力。
- 不向服务器上传扫描结果，不访问互联网，也不修改任意客户端配置。

## 页面结果

每个已检测到的客户端独立显示。其下按 MCP、Skill、插件分组；每项显示名称、版本、来源路径和状态。

状态只有三种：

- 启用：客户端当前可以使用该项。
- 禁用：本机存在该项，但客户端当前未启用或不可发现。
- 错误：无法判定状态，或其必要配置、命令、文件或本地服务已失效。

错误不再细分为读取失败、失效等类别。详情区域可展示原始且脱敏后的原因，便于员工自行排查。

## 识别规则

客户端扫描器各自负责读取其原生配置、目录和本地命令结果，再输出统一的展示项。页面层不自行推测配置含义。

MCP 同时参考配置和客户端实际加载结果，判断是否启用。Skill 根据 `SKILL.md`、所在目录以及所属插件的启用状态判断。插件以客户端登记的启用信息和插件清单为依据；插件缓存只能补充名称、版本和来源，不能单独判定为启用。

已检测到客户端但其中一类扩展无法读取时，其他可读取项继续显示；无法识别的项或扫描结果以错误状态呈现。没有检测到客户端时不显示空区域。

## 数据流

```text
打开扩展页面或点击刷新
  -> 检测 Codex 与 Claude Code
  -> 分别扫描 MCP、Skill、插件
  -> 归并为页面内存快照
  -> 显示分组结果与状态
```

扫描结果只保留在当前页面状态中。刷新会完全替换旧快照，避免把已删除或已变更的本地配置长期显示为当前状态。

## 实现边界

本地文件访问和客户端命令调用由 Tauri 原生层负责；Nuxt 页面只请求扫描命令并展示结果。扫描器不执行扩展提供的脚本，不启动 MCP 服务，不启动 Codex 或 Claude Code 的交互会话。

实现前需以当前安装版本核验各客户端的配置文件、Skill 根目录、插件登记位置和 CLI 输出。不能以缓存目录、历史版本目录或项目局部配置替代当前启用状态。

## 验收标准

- 已安装的 Codex 或 Claude Code 在打开页面后自动出现，未安装的客户端不显示。
- 每个已识别项只显示启用、禁用或错误之一。
- 插件缓存不会被单独显示为启用插件。
- 扫描不会写入本地配置、启动扩展、联网或上传数据。
- 一类扫描失败不会阻止同一客户端其他可读扩展显示。
