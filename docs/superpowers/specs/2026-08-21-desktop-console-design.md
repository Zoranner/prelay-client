# 桌面管理控制台设计

## 目标

将客户端从网页式管理台重构为紧凑、连续、面向重复操作的桌面控制台。供应商、接入和活动页面优先支持扫描、筛选、编辑和检查；工作台只承载统计概览。

## 应用框架

应用使用固定侧边导航、顶部连接上下文和可滚动的主工作区。侧边导航只负责模块切换，顶部只显示当前服务连接状态与地址，不重复展示页面内容。每个页面由标题栏、操作工具栏和一个主工作面组成。

供应商、接入和活动页面以表格为主工作面。创建和编辑使用右侧抽屉，详情在行展开区展示，避免页面跳转和多层卡片。工作台由摘要、请求趋势、结果分布及排行组成，不展示与活动页重复的明细。

## 视觉令牌

全局样式定义颜色、文字、间距、边框、圆角、层级和交互状态令牌。界面使用冷白底色、石墨文字和青绿色主操作色；成功、警告、错误只表达状态。页面和业务组件不得直接写入颜色值，组件通过令牌或语义变体获得视觉样式。

基础控件使用小圆角、细边框和清晰的键盘焦点；数据表格保持紧凑行高、固定表头和可横向滚动。页面区块不作为浮动卡片，只有表格容器、抽屉、统计项目和独立工具面使用边框或轻阴影。

## 组件边界

`components/base`、`input`、`container`、`navigation`、`overlay`、`display`、`feedback` 和 `layout` 仅包含通用组件。`components/business` 下按 `dashboard`、`activity`、`providers`、`interfaces` 划分领域组件。页面只负责数据加载、命令调用和组件组合。

通用组件提供语义化变体，不暴露页面专用颜色类。业务组件不直接实现重复的按钮、下拉、表格或反馈状态结构。

## 错误与状态

全屏错误通过通用 `ErrorState` 表达；具体标题、说明和恢复操作由业务页面或应用壳提供。空数据使用 `EmptyState`，加载使用 `LoadingState`，两者与错误状态保持独立。

## 验收标准

- 应用框架、主题令牌和基础控件不包含页面业务文案。
- 页面不直接定义颜色、重复表格结构或通用控件样式。
- 供应商、接入、活动和工作台符合各自的工作面职责。
- 现有管理命令、设置流程和全屏连接错误行为保持不变。
