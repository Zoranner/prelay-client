四种方案都要覆盖的状态

浮层不是只给正常数据设计的；状态文案和动作必须一起确定。

未接入

显示原因，不显示空窗口

标题 + “该供应商没有接入额度接口”；不出现 5 小时/7 天/月的空行。

查询失败

错误码 + 可读消息

保留上次成功读数时加“旧读数”chip；没有旧读数就只显示错误。

旧读数

值和读取时间一起出现

不能只写“旧”；必须说明“显示的是上次成功读数”。

共享限额

标题带“共享”

窗口按日/周/月显示，余额可缺省；不与个人套餐混淆。

查询中

Spinner + skeleton

不裸露“查询中”文字；前导槽放 Spinner，值区放 56×10 skeleton，跟正常单元格同一骨架。

建议

列表列顺序：名称 → 协议 → 状态 → 剩余额度 → 创建人 → 操作。 协议列保留，创建人在额度之后；Kimi 这种只有两个窗口的供应商固定保留第三个灰置环。

浮层选 A 摘要卡。每个窗口一行，进度条、可用金额、重置时间都在一行组里； B 分组卡作为备选，C 适合只看最紧窗口，D 适合高密度桌面用户。

你选一个浮层方案；选定后我再把列顺序、协议列移除和浮层一起落到实际组件。
