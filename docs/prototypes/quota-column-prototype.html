供应商额度列方案

同一组供应商数据，四种信息结构。当前问题不是单纯的审美： 未接入会空白、余额与窗口不是同一骨架、字号 10/11px 不在设计系统里、百分比没有窗口标签。

A · 单行 + 圆环 B · 单行 + 进度条 C · 两行 + 进度条 D · 三窗口明细 共同规则 建议

设计目标

一眼看出最紧的额度，不被图形噪音干扰。同一列在未接入、只有余额、多窗口、查询失败、旧读数下保持同一骨架； 行内只展示最紧窗口，完整窗口留在浮层。

  • 主角：额度列的最紧窗口
  • 调性：桌面工作台，紧凑、可横向对照
  • 记忆点：换了数据状态，不换单元格形状
  • 边界：不新增自绘图形；优先使用 @stellar/ui
A

单行 + 圆环

已选 保留现有视觉

固定前导槽 + 窗口标签 + 余额。改动最小，但圆环仍是自绘 SVG；多窗口只能看一条最紧百分比。

适合：希望保留现有圆环识别度，只先统一骨架和字号。 实现：复用现有 PlanRings，不新增自绘 SVG；缺失环位灰置虚线。
B

单行 + 进度条

推荐

所有窗口型都用同一条 @stellar/ui ProgressBar；行内显示最紧窗口标签、百分比和余额。最统一，也最容易扫读。

适合：供应商列表这种需要快速横向比较的场景。 代价：行内不再同时看到三个窗口；完整窗口要靠浮层。
C

两行 + 进度条

信息更全

第一行最紧窗口，第二行余额/重置或其他窗口。行高增加，但 172px 内不需要把信息挤在一行。

适合：额度是主要信息，行高可以略微增加。 代价：列表密度下降；第二行可能截断。
D

三窗口明细

详情型

5 小时、7 天、月各一行，完整表达三个窗口。信息最全，但行高接近翻倍，更像详情面板而不是列表单元格。

适合：供应商详情、额度抽屉或单独展开行。 代价：不适合主列表；行高和视觉噪音都会明显上升。

四种方案共用的规则

这些是无论选哪种方案都不应该退回去的底线。

列头统一为“剩余额度”，百分比都表示剩余；如果要显示“已用”，整套同步改，不能混用。
主值和次值统一 12px，数字使用 tabular-nums；不再出现 10px、11px 的局部字号。
未接入、待配置、查询失败必须有文字，不允许用空白单元格表示状态。
多窗口行内只显示最紧窗口；并列时取最小单位（5 小时优先于 7 天，7 天优先于月），完整窗口留在 Tooltip。
窗口不足 3 个时仍保留 3 个环位，缺失环灰置虚线；不能少画一个环。
只有余额时把金额提升为主值，前面加“余额”；不再让它像一条次要注释。
旧读数用 12px 的“旧”chip；状态色同时作用于文字和进度图形，不能只给图形上色。
状态 行内呈现 浮层
未接入 muted 状态 chip + 前导占位，不空白 “该供应商没有接入额度接口”
只有余额 币种图标 + “余额 ¥6.94”，金额为主值 币种、金额、读取时间
多窗口 最紧窗口标签 + 百分比；可选余额作次值 逐窗口列出剩余、金额、重置时间
旧读数 主值不变，末尾 12px “旧” chip 说明显示的是上次成功读数
查询失败 danger 状态 chip；有旧读数时仍显示旧值 + “旧” 错误码和可读消息

建议

当前选择 A。保留现有圆环识别度，统一为固定前导槽、单窗口标签、余额次级和 12px 字号； 窗口不足 3 个时仍保留 3 个环位，缺失环灰置虚线。

B 仍然是更彻底的统一方案：一条 @stellar/ui ProgressBar 可以把余额、窗口和共享限额压进同一骨架，也避开自绘 SVG。 C 适合额度确实是主信息的页面；D 更适合详情面板，不建议放进主列表。

本轮只做静态方案，没有改实际组件。选定方案后再按 @stellar/ui 的 ProgressBar/Tooltip 实现，并在 1440/1024、亮/暗主题下做实渲染验收。
